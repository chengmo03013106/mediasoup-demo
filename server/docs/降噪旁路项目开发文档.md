# 降噪旁路项目开发文档

> 版本：v1（最小闭环调试版）
> 日期：2026-08-24
> 状态：方案已冻结，待实现

---

## 一、项目目标

搭建一条**最小可用的音视频数据闭环**，用于喂数据给自研降噪服务做学习与调试：

```
音视频源(浏览器) ──▶ SFU ──▶ 降噪服务 ──▶ SFU ──▶ 观察端(浏览器)
```

**核心诉求**：不是生产级系统，而是调试工具。第一优先级是"把链路跑通"，而非"完美、健壮"。

### 明确不做的事（避免过度设计）

- ❌ SPOF 自动降级（调试用，服务挂了重启即可）
- ❌ 音画同步补偿
- ❌ 多房间隔离 / 容量评估 / 背压
- ❌ 健康检查重连（先手动重启）
- ❌ RTCP 回传（暂缓）
- ❌ 复杂 SSRC 反查（用固定值 + BroadcasterPeer 机制）

## 二、整体架构

### 数据流

```
浏览器A(麦克风) ──produce──▶ SFU #producerRouter
                                 │
                                 ├─ consumer ──▶ 观察端  (原始流, peerId="A", 用于对比)
                                 │
                                 ├─ consumer(旁路) ──▶ PlainTransport#出 ──UDP──▶ 降噪服务
                                 │                        (SFU connect 到降噪服务固定端口)
                                 │
   观察端 ◀─ consumer ── SFU ◀─ producer(回传) ◀── PlainTransport#进 ◀──UDP── 降噪服务
                (降噪流)      (BroadcasterPeer "denoiser")   (SFU 固定端口监听)
```

### 端口约定（旁路方向写死，回传走 BroadcasterPeer 协商）

| 方向 | 监听方 | 端口来源 | 说明 |
|------|--------|---------|------|
| 旁路（SFU → 降噪服务） | 降噪服务 | 降噪服务固定 | SFU 配置 `remoteIp` + `remotePort` |
| 回传（降噪服务 → SFU） | SFU | API 返回 | 降噪服务走 BroadcasterPeer 流程，端口由 SFU 分配、API 返回 |

### 关键角色

- **降噪服务**：主动通过 HTTP API 以 `BroadcasterPeer` 身份加入房间，走完整流程（建 transport → connect → produce）回传降噪流。**不跑 protoo，只跑 HTTP 客户端 + UDP 收发**。
- **SFU**：旁路 consumer 主动推流给降噪服务；回传流复用 BroadcasterPeer 机制自然转发给观察端（独立 peer 条目，A/B 分路）。

## 三、需要完成的功能

### 功能 1：旁路转发（SFU → 降噪服务）

当 speaker 上行 audio producer 时，SFU 自动：
1. 在 `#producerRouter` 上建一个旁路 PlainTransport（出方向，rtcpMux）。
2. `connect` 到降噪服务固定地址。
3. 为该 producer 建旁路 consumer（`ignoreDtx:false`, `enableRtx:false`）。
4. 同时**保留**原始流转发给观察端（用于 A/B 对比）。

### 功能 2：回传接收（降噪服务 → SFU）

1. 降噪服务以 BroadcasterPeer "denoiser" 加入房间。
2. 走完整 BroadcasterPeer 流程：`createPlainTransport` → `connectPlainTransport` → `produce` 回传降噪流。
3. 回传 producer 的 `appData.peerId = "denoiser"`，自然进入 `broadcasterPeer.on('new-producer')` 分支。

### 功能 3：回传转发（SFU → 观察端）

1. 回传 producer 由 BroadcasterPeer 机制自动转发给观察端，作为独立 peer "denoiser" 的音频流。
2. 观察端可对"原始流（peer A）"和"降噪流（peer denoiser）"分别静音，做 A/B 听音对比。

### 功能 4：防回环（天然成立）

回传流走 `broadcasterPeer.on('new-producer')` 分支，而旁路入口只在 `peer.on('new-producer')`（speaker 流），两条路径天然隔离，**无需额外标记**。

### 功能 5：配置开关

`processing.enabled` 布尔开关，关闭时走原始直连（不旁路、不接收回传）。

## 六、整体验收确认（端到端）

闭环跑通的最终验收标准：

- [ ] 浏览器 A 开麦克风 → 观察端能听到 A 的原始音频（原始流正常）
- [ ] 降噪服务收到 SFU 旁路的 opus RTP（可抓包/日志验证）
- [ ] 降噪服务回传后，观察端出现"denoiser"独立音频条目
- [ ] 观察端对"原始流"和"降噪流"分别静音，能明显区分两者
- [ ] 关闭 `processing.enabled` 后，旁路停止、回传停止，观察端仅原始流
- [ ] 无 TS 编译错误、无运行时崩溃

## 附录：降噪服务调用的 HTTP API 接口

| 顺序 | 方法 | 路径 | 作用 | 返回 |
|------|------|------|------|------|
| 1 | POST | `/rooms/:roomId/broadcasters/denoiser` | 创建 BroadcasterPeer | 201 |
| 2 | POST | `/rooms/:roomId/broadcasters/denoiser/join` | 加入房间 | 200 |
| 3 | POST | `/rooms/:roomId/broadcasters/denoiser/plain-transports` | 建回传 transport | `{transportId, ip, port, rtcpPort}` |
| 4 | POST | `/rooms/:roomId/broadcasters/denoiser/plain-transports/:id/connect` | connect | 200 |
| 5 | POST | `/rooms/:roomId/broadcasters/denoiser/plain-transports/:id/produce` | 回传 produce | `{producerId}` |

> 注：回传端口用配置写死 `echoPort`，降噪服务可直接按固定端口回传，无需读 API 返回的动态端口。
